## Blocking finding 1 — structural freshness is insufficient

`freshness-audit.yaml` proves exact prompt-string overlap is zero, but exact-string freshness is not enough after Gate A selected-model outcomes have already been observed. Multiple Gate B cases are near-isomorphic or even semantically identical to Gate A executed benchmark cases.

Examples include:

- Gate B `math-23`: multiplicative inverse of 17 modulo 43, answer 38 — semantically the same task/constants as Gate A v1.2.2 `math-17`;
- Gate B `math-39`: the same `T_0=T_1=1`, `T_n=T_(n-1)+T_(n-2)`, ask for `T_8=34` construction as Gate A v1.2.2 `math-18`;
- Gate B `math-08`: 90-degree counterclockwise coordinate/vector rotation — the same construction as Gate A v1.2.2 `math-04` with changed coordinates;
- Gate B `math-33`: maximum plane regions from lines in general position — the same construction as Gate A v1.2.2 `math-06` with only the line count changed;
- Gate B `math-35`: surjection counting — the same inclusion-exclusion skeleton as Gate A v1.2.2 `math-30` with the codomain size changed;
- Gate B `math-37`: bounded compositions with identical upper-bound/inclusion-exclusion structure to Gate A v1.2.2 `math-48`;
- Gate B `math-43`: Catalan-number evaluation immediately adjacent to Gate A v1.2.2 `math-41`.

Coding also contains many repeated task skeletons from Gate A (`count_vowels`, `chunked`, `edit_distance`, `count_islands`, `knapsack`, interval merge, coin change, etc.). Coding reuse is less consequential to the primary routed-vs-General delta because both policies currently route Coding to General, but it still contradicts the intended fresh mixed benchmark.

Because Gate B's treatment advantage is expected to come primarily from Math routing, Math structural reuse is a material methodological confounder. B2/B3/B4 must not proceed on v1.0.0.

## Blocking finding 2 — router is using handoff/output-contract cues

`router-v1/router.py` counts strings such as `python 3.10`, `python or unlabeled`, `implementation block`, and `return python`. Those phrases are deliberately inserted into every Coding benchmark prompt by the benchmark's model-output contract. Math routing similarly benefits from output-contract words such as `integer` and `fraction`.

This does not expose a hidden label file, but it makes the 96/96 routing result partly a benchmark-format classifier rather than a task-semantic router. Architecturally, Dexinode should select the skill before applying the selected skill's handoff/output contract.

The revision should separate the router-visible semantic task text from the model-facing handoff/output contract. The router must be evaluated only on the semantic task text (or an equivalent mechanically verified contract-stripped view), while both model policies receive the same frozen model-facing prompt for the selected task.
